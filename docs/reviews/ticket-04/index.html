What failed before the implementation?

The new folder test received article rows instead of the three filter folders. Filter navigation failed as an unknown library parent. Completion and artwork tests lacked the filter-specific notifications. Each case passed after its corresponding implementation.

What do the automated checks cover?

Folder order and flags; lookup and malformed IDs; eligibility and history; filtering before paging; empty results versus errors; restart and offline browsing; unknown membership; complete totals beyond the detail cap; shared articles; multiple completions; all 200 retained issue memberships; narration and artwork updates.

What does the device smoke test establish?

Its source compiles. When executed, it connects to the real service using a cached fictional catalog and checks folder metadata, lookup, errors, subscriptions, completion notifications, and unchanged idle-session state. It does not start audio. Compilation and this browser demo do not establish that the device test or active-playback acceptance passed.

03 /

Rules & scope

  • Known unnarrated articles are excluded. Unknown narration remains eligible.
  • Partly played articles remain Unlistened until the existing completion threshold qualifies them.
  • Replaying keeps the listened status. Shared articles update every affected issue.
  • Filter before pagination and preserve article order and playable IDs.
  • Known empty membership shows 0/0 listened. Unknown membership shows Progress unavailable.
  • The existing 100-article browse cap remains. The whole-issue summary uses complete membership.
  • Browse and folder lookup use metadata, without resolving audio or exposing stream URLs.

Still to verify on DHU / car

The extra navigation level, touch and rotary use, folder and article-list heading visibility, empty filters, live completion during playback, reconnect, and phone-background behavior. Backend duration contracts and rewind compatibility remain separate work.
